# Published original verification lifecycle

This is a single-use, externally prepared synthetic fixture, not a persistent staging test account. Required secret field:lifecycle=single_use_operator_cleanup. The workflow has no service-role key and cannot perform Storage DELETE under the current authenticated policies. Do not widen those policies or add a service key to the runner just to make it repeatable.

Before dispatch, use a clean approved main checkout and verify the exact served staging SHA. Prepare a fresh qa-published-evidence-UUID project in the designated QA tenant, dedicated confirmed Auth identity/member/grant, task/approved report/media/link and explicitly published evidence; one known synthetic PNG in the private media bucket. Validate every parent, tag, uploader, object path and checksum. The temporary secret contains only scoped QA credentials/public anon key; refuse to overwrite an unrelated existing secret.

Run once. The runner intentionally withdraws/restores fixture publication, revokes its customer grant and creates/revokes one exact-tag project proof share. It also creates/uploads one exact-tag synthetic PDF document. Auth sessions for the temporary identity are globally revoked in finally. The sanitized proof returns cleanup_required=true. A successful test does not mean cleanup is complete.

After success OR failure, remove the temporary repository secret immediately. With the operator's existing server access, reconcile exact artifacts before another dispatch: inspect only the tagged fixture's project/report/source/grant/user and exact-tag share/document, never business records. A lost document-upload response is recoverable only by listing that synthetic project's documents folder, verifying the deterministic fixture PDF checksum and rejecting unknown contents. Delete exact task blobs through Storage API and verify absence; check for unrelated document references before deleting the fixture document (events cascade). Delete the exact fixture evidence/link/share/grant/report/task/media/member/project and Auth identity, verify absence, revoke the owner's task-local session, and scrub private credential/run files. Operational audit traces remain retained.

Never restore and silently reuse a grant from a prior test. Its initial active-state and prior-artifact-absence assertions deliberately reject replay. If a run was interrupted, finish exact cleanup first, then create a new tagged fixture and new temporary credentials before dispatch. This same lifecycle applies to local execution from approved main. Owner QA credentials and service access stay private; do not put them in this runbook or proof artifacts.
