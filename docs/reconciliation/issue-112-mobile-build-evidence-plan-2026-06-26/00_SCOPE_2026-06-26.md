## Scope of this PR

- No iOS code changes.
- No Android code changes.
- No web/backend/API/auth/RBAC changes.

- No broad merge of any mobile / `release/mobile-pilot-rc` / design branch.

## Why an evidence plan is required before claims
- Per `AGENTS.md` and `docs/CURRENT_PROJECT_TRUTH_INDEX.md`: **no TestFlight/App Store/Google Play/pilot-live claim without verified build/deployment evidence**, and latest `main` is **not** assumed deployed without `buildStamp` evidence.
- The PR #140 audit confirmed mobile **source presence** only — not runtime/build verification. iOS native build/UITest needs **Xcode + simulator/device**; Android needs **Android SDK / Gradle / emulator or device**. Neither was executed.
- This plan converts "what must be true" into a concrete, checkable artifact list so a future operator (with the right toolchain) can produce evidence without ambiguity, and so no premature claim is made in the interim.

## Out of scope
- Running `xcodebuild`, `gradlew`, emulators/simulators, or any CI workflow.
- Any signing, archive, upload, TestFlight, or Play Console action.
- Any change to credentials/secrets (none are included here).
