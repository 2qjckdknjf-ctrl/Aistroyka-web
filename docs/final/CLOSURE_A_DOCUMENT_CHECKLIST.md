# Closure A — документы менеджера: чеклист ручной проверки

Использовать на **staging** или **production** с ролью менеджера (`canManageProjects`). Отмечать фактическим результатом.

---

## Подготовка

- [ ] Есть проект и доступ к `/dashboard/projects/[id]` (вкладка / блок документов).

## Сценарий A — счастливый путь до архива

- [ ] Создать документ (тип + название) → статус **Черновик**.
- [ ] Загрузить файл допустимого размера → статус **Загружен**, ссылка «Открыть» ведёт на публичный URL объекта.
- [ ] **Отправить на проверку** → **На проверке**.
- [ ] **Одобрить** → **Одобрен** (при необходимости проверить историю).
- [ ] Перевести в **Архив** (если доступно действием в UI или тем же PATCH, как принято в продукте).

## Сценарий B — отклонение

- [ ] Повторить шаги до **На проверке**.
- [ ] **Отклонить** → **Отклонён**, событие в истории.

## Сценарий C — запрос правок

- [ ] Повторить шаги до **На проверке**.
- [ ] **Запросить правки**, ввести текст комментария → статус **Нужны правки**, комментарий виден в строке / истории.
- [ ] **Повторно на проверку** → снова **На проверке**.

## Сценарий D — целостность загрузки

- [ ] Симулировать или зафиксировать на код-ревью: при ошибке сохранения строки после upload объект в Storage не остаётся сиротой (откат в `upload/route.ts`).

## Регресс связей

- [ ] Создать документ с привязкой к вехе — в таблице отображается название вехи.
- [ ] При наличии данных — ссылки на отчёт / задачу кликабельны и ведут в нужные экраны.

---

После прохождения приложить к тикету спринта краткую пометку (среда, дата, результат).
