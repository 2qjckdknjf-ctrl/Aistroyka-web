## Learned Workspace Facts

- Aistroyka is a monorepo; web application lives in apps/web (Next.js, App Router).
- Root build: from repo root run `bun install` and `bun run build` (builds packages/contracts then apps/web).
- Production runtime and DNS ownership is **Cloudflare Workers** (`apps/web/wrangler.toml`, OpenNext); use `bun run cf:build` then Wrangler deploy, and verify apex/www routes through Cloudflare when making production readiness claims. **Canonical production domain is `aistroyka.ai`** (including `www.aistroyka.ai`); `aistroyka.com` and `www.aistroyka.com` are redirect-only entry domains (301 to `https://aistroyka.ai`, preserving path and query)—do not serve the app independently from `.com`. Do not run `bun run build` and `bun run cf:build` in parallel—concurrent Next/OpenNext work can corrupt `apps/web/.next`; run sequentially or remove `apps/web/.next` before retrying. Web UI is App Router under `apps/web/app` (no `pages/` tree); root-level error UI uses `app/global-error.tsx`—reintroducing `pages/*` (for example a custom 500 page) can destabilize standalone or OpenNext builds, so validate with `cf:build` before relying on it. **AI runtime is `apps/web` only** (no repo Python `backend/`); canonical live gate `bash scripts/smoke/ai_live_provider.sh --require-live`; supplementary smokes `scripts/smoke/ai_*.sh`; architecture truth in `docs/ai/AUDIT_AI_RUNTIME_ARCHITECTURE_TRUTH.md`.
- iOS: AiStroykaManager and AiStroykaWorker (shared in `ios/Shared`); checked-in Xcode projects include **UITest** targets (`WorkerSmokeUITests`, `ManagerSmokeUITests`) for simulator smoke (login + `pilot_*` ids); Layer B live pilot E2E uses gitignored `ios/Config/.uitest-e2e-credentials` via `AISTROYKA_E2E_CRED_FILE`—do not bundle E2E credentials in SPM Shared resources; PRs that touch `ios/` (excluding **markdown-only** changes under `ios/**/*.md` for the UITest workflow) run `.github/workflows/ios-ui-smoke.yml`; use **workflow_dispatch** for a manual run; locally run `ios/scripts/run-ios-uitest-smoke-local.sh`, `ios/scripts/run-ios-e2e-integration-local.sh`, or `ios/scripts/ci-pick-iphone-simulator-udid.sh` + `xcodebuild test` (see `ios/README.md`). Android mirrors (`android/shared`); WorkerLite is deprecated as the primary product name.
- Local iOS config: ios/Config/Secrets.xcconfig (gitignored) and Secrets.xcconfig.example; both apps use the same xcconfig.
- Public site and dashboard coexist; locale routes under [locale]; public pages under (public), dashboard under (dashboard); web i18n uses next-intl message files for en/ru/es/it.
- API routes live under apps/web/app/api/; treat /api/v1/* as canonical, and do not change tenant/auth logic without necessity. Mobile sync 409 conflict responses expose `serverCursor` (a `server_cursor` alias may appear) for reconciliation—follow docs/runbooks/MOBILE_SYNC.md. Field clients sending `x-client: ios_lite` or `android_lite` are restricted to an allow-list in Edge `middleware.ts` (`apps/web/lib/api/lite-allow-list.ts`); disallowed `/api/v1/*` paths return 403 for those profiles.
- Docs and phase reports go under docs/ and subdirs (e.g. docs/audit/, docs/final/, docs/mobile-rebuild/, docs/deploy-fix/, docs/pilot-launch/). Canonical full-project audit on main: `docs/audit/AUDIT_2026-06-11_full-project-audit-v2.md`. Phase 13 roadmap closure verdict: **CONDITIONAL YES** in `docs/product/PHASE13_ROADMAP_CLOSURE.md` — the mega-roadmap defines no separate Phase 14 product scope after Phase 13 (section 14 is the execution template; §15 is the strategic verdict). Pilot audit: `bun run audit:pilot` at repo root; preflight env for pilot smoke with `bun run smoke:pilot:check` (use `--strict` to fail when `ops/metrics` auth is missing); Playwright specs live under `apps/web/tests/e2e` with `PLAYWRIGHT_BASE_URL` as baseURL; scoped pilot run `bun run --cwd apps/web e2e:pilot`; env template `.env.pilot.example`; local strict smoke runs often require loading both `/.env.pilot` and `apps/web/.env.local` plus aligning `BASE_URL`/`PLAYWRIGHT_BASE_URL` to active local app URL (`NEXT_PUBLIC_APP_URL`, often `localhost:3001` when `3000` is busy); artifacts under docs/audit/artifacts/. Guests may redirect to `/[locale]/login?next=` (not only the bare locale root); dashboard audit specs that exercise auth expect `E2E_USER_EMAIL`/`E2E_USER_PASSWORD` (or legacy `SMOKE_*`).
- Environment variables for production are documented in docs/ENVIRONMENT-VARIABLES.md; required: NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, NEXT_PUBLIC_APP_URL. For Cloudflare/OpenNext (`cf:build`), those `NEXT_PUBLIC_*` values must be present at build time—they are inlined into the client bundle, so Worker runtime secrets alone do not satisfy client-side checks (e.g. login). Apple/Telegram provider buttons on login/register only render when configured (Supabase Apple provider; `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` or `TELEGRAM_BOT_USERNAME` plus `TELEGRAM_BOT_TOKEN`).
